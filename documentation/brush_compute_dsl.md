# Brush Compute DSL — Design Proposal

*Status: design only. Implementation deferred until the in-flight sculptcore
refactor lands.*

## Context

Sculptcore (`sculptcore/source/brush/`) currently executes brushes as templated
C++ functors on a per-spatial-node basis (`brush_executor.h` →
`BrushCommandDef::exec(CommandCtx<TYPES> &)`). The `DRAW` brush is ~5 lines
(`brushes/draw.h`). Falloff is a hardcoded smoothstep in
`CommandCtx::strength` (`brush_command.h:55`). Properties flow JS→wasm via
`props::StructProp` (`brush.h`, `props/prop_struct.h`).

The TS side declares richer brush data: ~17 sculpt tools
(`scripts/brush/brush_base.ts:59`), procedural textures with 3 coord modes
(`scripts/texture/proceduralTex.ts:58` — `GLOBAL`, `VIEWPLANE`, `VIEW_REPEAT`)
and flags (`CURVED`, `CONSTANT_SIZE`, `ORIGINAL_CO`, `RAKE`, `FANCY_RAKE`),
Curve1D falloff, dyntopo, color, mask. The TS pipeline lands in
`scripts/editors/view3d/tools/sculptcore_ops.ts:189`
(`execBrush(brushType, nodes, origin, normal)`).

Goal: a single brush kernel source that targets WebGPU (WGSL), Vulkan
(SPIR-V), CUDA, HIP, OpenCL, and the existing native/wasm C++ executor as the
reference. Must express:

1. Local per-vertex brushes (Draw, Clay, Scrape, Sharp, Pinch, Inflate, Mask).
2. Global brushes (Kelvinlet, hexahedral cage / pose) that consume host-side
   BVH queries.
3. Brush textures (image + procedural) with selectable coord spaces, including
   stroke-curve-warped coordinates.
4. Optional analytical differentiation (deferred — design must leave room).

---

## Proposed Language: `sbrush`

A small statically-typed DSL with C/HLSL-like surface syntax, compiled to a
sculptcore-owned SSA IR (`BrushIR`), then lowered to each backend. Brushes
live as `.sbrush` files in `sculptcore/source/brush/kernels/` and are
processed at build time (codegen output checked in / regenerated by
`make.mjs`).

### Why not Slang directly

Slang covers HLSL/GLSL/SPIR-V/CUDA/CPU and has autodiff, but: (a) no
first-class WGSL/OpenCL/HIP emit today; (b) brings a heavy compiler dep;
(c) its semantic model doesn't naturally express the brush execution shape
(per-node iteration, host-side BVH queries between stages). Slang is a viable
Plan B if hand-rolling lowerings becomes too painful — the IR is designed so
a Slang frontend could be added later.

### Surface syntax (sketch)

```sbrush
// brushes/draw.sbrush
@brush("draw")
brush Draw {
  // Auto-marshalled from sculptcore::brush::Brush props (StructDef).
  uniform float strength;
  uniform float radius;
  uniform bool  invert;
  uniform Falloff falloff;   // built-in: Curve1D or analytic
  uniform Tex2D  texture;
  uniform TexCoordSpace coordSpace;

  // Per-stroke / per-dot context — matches CommandCtxBase fields.
  ctx float3 surfacePos;
  ctx float3 surfaceNo;
  ctx mat4   renderMatrix;
  ctx StrokePath stroke;

  // Local per-vertex stage. Compiles to:
  //   - C++: existing executor loop body.
  //   - WGSL/SPIR-V/CUDA: compute kernel, one thread per vertex in node.
  vertex void apply(inout Vertex v) {
    float d = distance(v.co, surfacePos);
    float t = falloff(d / radius);            // expands to lut/curve lookup
    float w = strength * t * (1.0 - v.mask);
    float texw = sampleBrushTex(v.co, v.no);  // honors coordSpace + stroke
    v.co += surfaceNo * (w * texw * (invert ? -1.0 : 1.0));
  }
}
```

Global brushes get a different stage signature:

```sbrush
@brush("kelvinlet")
brush Kelvinlet {
  uniform float strength, radius, mu, nu;
  ctx float3 grabFrom, grabTo;

  // Optional reduce stage runs once per stroke step before vertex stage.
  // Can request host-side BVH queries — these are filled by the runtime
  // (sculptcore::spatial::SpatialTree::filterNodes / nearest / raycast)
  // and bound as read-only buffers.
  reduce void prep(out KelvinletState s) {
    s.a = (1 + nu) / (2 * mu);
    s.b = s.a / (4 * (1 - nu));
    s.c = 2.0 / (3.0 * s.a - 2.0 * s.b);
  }

  vertex void apply(inout Vertex v, in KelvinletState s) {
    float3 r = v.co - grabFrom;
    float  e = sqrt(dot(r,r) + radius*radius);
    float3 u = ((s.a - s.b) / e + s.b * dot(grabTo, r) * r / (e*e*e)) * grabTo;
    v.co += strength * u;
  }
}
```

Brushes that need *neighborhood* iteration (smooth, fair, pose with cage) get
a `neighbors` accessor that the compiler legalizes per backend (per-vertex
ring on CPU; preloaded into shared/group memory or fetched via indirection
buffer on GPU):

```sbrush
vertex void apply(inout Vertex v) {
  float3 avg = float3(0);
  int n = 0;
  for (let nb of neighbors(v)) { avg += nb.co; n++; }
  v.co = mix(v.co, avg / n, strength * falloff(distance(v.co, surfacePos)/radius));
}
```

### Type system

- Primitives: `int`, `uint`, `bool`, `f16`/`f32`/`f64`, vector
  (`float2..4`, `int2..4`), `mat3`, `mat4`, `quat`.
- Aggregate: `struct`, fixed `Array<T,N>`, ABI-stable layout matching
  `litestl::math` types so wasm-side mirrors are zero-cost.
- Resource: `Buffer<T>`, `Tex2D`, `Tex3D`, `Falloff`, `StrokePath`,
  `BVHQueryResult`.
- Qualifiers: `uniform` (brush props), `ctx` (per-step state), `in` / `out` /
  `inout`, `shared` (workgroup).
- No pointers, no recursion (matches WGSL/Vulkan/OpenCL-1.2 constraints; CUDA
  happily downgrades).

### Execution model

Three optional stages per brush, called by the host (`brush_executor.h`):

| Stage | When | Maps to |
|---|---|---|
| `host` (optional) | Once per stroke dot, on CPU | Runs `BVH.filterNodes` / `nearest` / `raycast`, populates `BVHQueryResult` buffers and `ctx` state. C++ only — never lowered. |
| `reduce` | Once before `vertex`, on the selected backend | Single-threaded scalar block; produces a small struct passed to every vertex thread. |
| `vertex` | Per-vertex parallel | The hot kernel. Lowered to compute shaders on GPU backends; lowered to the existing `vertexIter` loop on CPU. |

Existing `brush_executor.h:execBrush` becomes the dispatcher: chooses backend
per registered brush, runs `host` natively, marshals uniforms via
`props::StructProp`, launches the compiled kernel for the matching backend.

### Falloffs

`Falloff` is a tagged-union uniform:
- `Spherical { Curve1D }` — table-lookup, current behavior.
- `Cube { Curve1D, axisCurve }` — `max(|dx|,|dy|,|dz|)/r`, supports the
  existing `SQUARE` brush flag.
- `Linear { Curve1D, dir }` — for the stroke-line falloff
  (`brush_base.ts: LINE_FALLOFF`).
- `Analytic { kind: smoothstep|gaussian|… }` — closed-form, branchless.

Curve1D LUTs ship as a `Buffer<float>` (256 entries) bound automatically; the
IR exposes `falloff(x)` as a single intrinsic, so backend lowering picks
LUT-fetch vs. analytic.

### Brush textures and coord spaces

`sampleBrushTex(p, n)` is an intrinsic that expands based on `coordSpace`:

| Mode | Source (TS) | Coord computation |
|---|---|---|
| `GLOBAL` | `TexUserModes.GLOBAL` | object-space `p` |
| `VIEWPLANE` | `TexUserModes.VIEWPLANE` | `(renderMatrix * p).xy` |
| `VIEW_REPEAT` | `TexUserModes.VIEW_REPEAT` | tiled viewplane |
| `STROKE_CURVED` | `TexUserFlags.CURVED` | nearest-stroke-segment arc-length + lateral offset, from `StrokePath` buffer |
| `PROJECTED` | new | project along `surfaceNo` onto its tangent plane |

`StrokePath` is a uniform-resident ring buffer of recent stroke samples
(pos, normal, distance-along, frame). `STROKE_CURVED` reads it; the compiler
legalizes ring-buffer reads per backend (uniform array on CPU/CUDA, storage
buffer on WGSL/SPIR-V).

Procedural textures from `proceduralTex.ts` are already GLSL-generating
(`createShaderClass` → `genGlsl`). The DSL adopts the same generator surface:
a `@texture` declaration whose body is plain `sbrush` code, callable as
`tex.eval(p, n)` from any brush. Image textures become `Tex2D` with a
bilinear sample intrinsic.

### IR (`BrushIR`)

Small SSA, ~30 ops: `add/sub/mul/div/fma`, `dot/cross/length/normalize`,
`sample_tex/sample_curve/sample_falloff`, `read_attr/write_attr` (`co`, `no`,
`mask`, `color`, custom layers), `neighbor_begin/next/end`, `bvh_query`
(host-only). Stored in `sculptcore/source/brush/kernels/ir/` as plain C++
data structures using existing `litestl::util::Vector` (no STL).

### Backends and lowering

| Backend | Output | Notes |
|---|---|---|
| C++ (native + wasm) | C++ inline functor matching the existing `template<CTX> static void exec(CTX&)` shape | Drop-in replacement for hand-written brushes under `brushes/`. Build-time codegen, no JIT. |
| WebGPU | WGSL | One workgroup per spatial node; `unique_verts` indirection via storage buffer. Tint not needed — emit directly. |
| Vulkan | SPIR-V | Emit via `spirv-tools` or via WGSL+Tint+`spirv-cross` round-trip. Direct SPIR-V emit is leaner. |
| CUDA / HIP | `.cu` / `.hip.cpp` | Same source modulo `__device__`/`hipLaunchKernel` prelude — one lowering, two prelude headers. |
| OpenCL | OpenCL C | Distinct enough to warrant its own emitter (no templates, address-space qualifiers). |

The C++ emitter is the reference. CI runs every brush through *every*
backend's syntactic compile, plus the C++ build executes a golden-output test
on a fixed mesh (`tests/test_brush.cc` already wires this pattern).

### Analytical differentiation (deferred)

The IR is in three-address form with pure intrinsics, which makes forward-mode
dual-number transformation a single IR pass: replace each `float` SSA value
with `(value, dvalue)` and rewrite ops mechanically. Reverse-mode is a
separate pass over the same IR (tape per basic block, brushes have no loops
over unbounded data except neighbors — neighbor loops get unrolled-by-runtime
or use accumulator tapes).

Design decisions taken *now* to keep this open:
- All intrinsics declare derivatives in a single table
  (`kernels/ir/intrinsics.cc`).
- No raw pointer arithmetic, no aliasing of `inout` params with other reads.
- `falloff` and `sample_tex` get analytical gradients available (LUT tex uses
  central-difference fallback; analytic falloffs use closed form).

## Critical files

- `sculptcore/source/brush/brush_executor.h` — dispatcher; gains a backend
  selector and uniform-marshalling for compiled kernels.
- `sculptcore/source/brush/brush_command.h` — `CommandCtxBase` already carries
  everything the `ctx` qualifier needs; extend with `StrokePath` and a
  `BVHQueryResult` slot.
- `sculptcore/source/brush/brushes/` — existing hand-written brushes
  (`draw.h`) become emitter outputs; sources move to `kernels/*.sbrush`.
- `sculptcore/source/brush/kernels/` (new) — `.sbrush` source files, `ir/` IR
  datastructures, `emit_cpp.cc`, `emit_wgsl.cc`, `emit_spirv.cc`,
  `emit_cuda.cc`, `emit_opencl.cc`.
- `sculptcore/source/brush/compiler/` (new) — lexer/parser/sema, ~2–3K lines,
  no external deps; mirrors litestl style.
- `sculptcore/source/spatial/spatial.h` — already exposes `filterNodes`;
  `host` stages call it directly.
- `scripts/texture/proceduralTex.ts` — TS-side procedural tex; the DSL adopts
  its generator pattern so procedural textures stay authored where they are.
- `scripts/editors/view3d/tools/sculptcore_ops.ts:189` — call site stays
  unchanged; backend selection happens inside `execBrush`.
- `sculptcore/make.mjs` — adds a `codegen` step that runs the `sbrush`
  compiler over `kernels/*.sbrush` before configure.

## Phasing

1. **Wave 1 — IR + C++ emitter, single backend.** Re-express `draw.h` as
   `draw.sbrush`, emit C++ identical to the current handwritten file.
   Regression-test via `test_brush.cc`. Pure refactor — no behavior change.
2. **Wave 2 — Falloff, mask, neighbors, brush textures.** Port Clay, Smooth,
   Pinch, Sharp, Inflate; bring `Falloff` and `sampleBrushTex` online; ship
   coord-space `GLOBAL`/`VIEWPLANE`/`VIEW_REPEAT`/`STROKE_CURVED`.
3. **Wave 3 — WGSL backend behind a feature flag.** GPU path for
   Draw/Clay/Smooth on a static mesh; validate against C++ output
   bit-for-bit-modulo-fp.
4. **Wave 4 — Global brushes.** `host` stage, `reduce` stage,
   `BVHQueryResult`; Kelvinlet + simple pose (hexahedral cage as a uniform
   array of 8 control points).
5. **Wave 5 — SPIR-V / CUDA / HIP / OpenCL emitters.** One per cycle; CI gates
   on syntactic compile.
6. **Wave 6 (deferred).** Forward-mode autodiff pass; expose `grad_apply` for
   brushes that want it (e.g. constraint solvers, optimization-based
   smoothing).

## Verification

- `node make.mjs test native` runs `test_brush.cc` golden-output checks;
  extend to a per-backend `test_brush_codegen` that compiles every emitted
  kernel.
- TS-side: existing `sculptcore.paint()` modal already exercises the Draw
  path end-to-end through the WASM module; no UI change required for Wave 1.
- Wave 3+: a `--sculpt-backend=wgsl|spirv|cpp` debug flag in
  `scripts/editors/view3d/tools/sculptcore_ops.ts` lets the user A/B
  backends on the same stroke.
